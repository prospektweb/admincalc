# Свойства торговых инфоблоков калькуляции

## Быстрая корректировка поддерживаемого состава

**Единственный редактируемый состав:** `resources/catalog/trade-properties.json`.
Для добавления или изменения свойства править этот файл и увеличить `revision`.
Не добавлять `CIBlockProperty::Add/Update` в installer, редактор формы,
пересчёт или разовый CLI-скрипт для свойств Calc. Действие в ЦУ читает этот файл;
таблица «Подробнее», план несоответствий и запись используют один состав.

Запись: `role` (`products`/`offers`), `fields`, `enums`, `description`.
Каждое значение списка имеет `VALUE`, стабильный `XML_ID`, `SORT`, `DEF`.
`aliases` допускаются только для известных прежних кодов того же свойства.
ID инфоблоков, свойств, перечислений и HL-записей в состав не включать.
Свойства HL имеют переносимое имя таблицы; содержимое справочников не импортируется.

После изменения: `php tests/trade_property_plan_test.php`,
`php tests/trade_property_service_test.php`, PHP lint и соответствующие
интеграционные проверки FrontCalc/ЦУ. Выпустить согласованные пакеты и проверить
настоящие Подробнее → план → подтверждение → применение → повторное чтение.
Обновление установленного пакета само не применяет новую схему.

## Контракт

Первая функция Calc в ЦУ — «Свойства торговых инфоблоков». «Создать» открывает
план. Запись требует подтверждения перечисленных изменений и свежего hash плана.
После первого явного применения кнопка становится «Обновить», включая случай,
когда свойство позже удалили. Состав и реестр принадлежат Calc; optional модули
не являются основанием убрать определение из состава.

Чтение и установка Calc не меняют торговую схему. Срочность и хэш состояния
не создаются скрыто редактором формы или массовым пересчётом. Операционная запись
значений свойства, товара/ТП и цены остаётся у своих модулей.

**Согласованное исключение 14.10.2026:** FrontCalc создаёт единственное собственное
свойство-хеш своим установщиком и хранит полную immutable запись в своей таблице.
Ни новый хэш, ни девять прежних `FRONTCALC_*` не входят в состав Calc. Старые
свойства/ID и расчётные позиции этим действием не удаляются. Миграцией и
совместимостью старых корзин управляет владелец FrontCalc.

Пара товаров/ТП берётся из точных сохранённых настроек витрины, независимо от
регистрации FrontCalc. Если настроек ещё нет, допустима только единственная
штатная SKU-пара, привязанная к явно настроенному `document_site_id` Calc.
Первый найденный каталог не выбирается. Явное применение закрепляет пару в
настройке Calc `trade_property_catalogs`; последующее расхождение с витриной
останавливается до согласованного переподключения.

Обновление сохраняет существующие ID и enum IDs/XML_ID. По сохранённому реестру
можно восстановить изменённый CODE того же ID. Известные aliases цвета также
сохраняют ID. Неизвестные свойства и дополнительные значения списков не удаляются.
Удаление свойства средствами Bitrix удаляет его значения: создание отсутствующей
схемы не обещает восстановления удалённых пользовательских данных.

Дубликаты кода/XML_ID требуют устранения причины. Смена типа и сокращение MULTIPLE
у заполненного свойства требуют отдельной миграции; в слайдере они заблокированы.
Пустое свойство допускает восстановление типа после проверки native значений.
Остальные безопасные строки
можно применить. Отсутствующий HL-справочник — отдельная зависимость, его контент
не выдумывается. Перед записью сохраняется backup состава/метаданных в
`bitrix/backup/prospektweb.calc/trade-properties`, затем выполняется native readback.
Подтверждение проходит через admin-only POST/CSRF ЦУ, plan CAS и именованный lock.

## Inventory прежних writers

| Место | Новый контракт |
|---|---|
| `lib/Documents/UrgencyProperty.php`, `prepareUrgencyProperty` | Read-only проверка; отсутствие направляет в новую функцию |
| `lib/Services/BatchRecalculateService.php::ensureHashProperty` | Проверяет `CALC_STATE_HASH`, не создаёт его при пересчёте |
| `lib/Install/CatalogPropertyCodeMigrationService.php` | Не переименовывает схему; известные aliases в центральном плане |
| `lib/Deployment/CatalogSchemaDeploymentService.php` | Старый общий профиль не пишет CALC/legacy FRONTCALC; другие свойства вне данного scope |
| FrontCalc `install/index.php`, InstallDB/InstallFiles, legacy metadata CLI | Отдельная authority FrontCalc; не переносится по прямому уточнению владельца |
| Исторический add-only перенос каталожных зависимостей 09.09.2026 | Разовая операция до нового контракта; не повторять как установщик |

Schema ресурсных справочников Calc, свойство `STAGE_GROUPS` старого графа,
свойства PartnerManager, PropValManager, поля заказа/корзины и UF/HL других модулей
**не являются свойствами калькуляции торговых инфоблоков** и не переносятся.
Legacy `CALC_PRESET` и `FRONTCALC_CONFIG` сохранены при наличии, но не создаются
для документной архитектуры. Привязки документа к товарам хранятся в Calc.
